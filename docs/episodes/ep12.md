### Query 1 — RSI Screener (~3 min)
> **Prompt:** "What tickers in my database are technically oversold right now? Show me anything with RSI below 30 in the last 30 days, sorted by how oversold they are."

**What Claude does:**
1. Calls `list_tables` to find `ohlcv`
2. Calls `query_sql` with: `WHERE rsi_14 < 30 AND date >= CURRENT_DATE - 30 days ORDER BY rsi_14 ASC`
3. Returns a formatted table with ticker, date, price, RSI, volume

**Walk through the output:** pick one name and ask a follow-up — "what's the chart pattern on that one over the last month?" Claude pulls OHLCV history and describes the trend.

### Query 2 — Options Flow Screener (~3 min)
> **Prompt:** "Show me unusual options activity — find contracts where volume is more than 2x their open interest, for any ticker in my database."

**What Claude does:**
1. Calls `get_options_chain` (or `query_sql` on `options_greeks`)
2. Filters for `volume / open_interest > 2` and `volume > 500`
3. Returns a table of the most active contracts

**Explain what this means:** when volume exceeds open interest in a single day, it means more contracts traded today than exist in total outstanding positions. This sometimes signals institutional activity or informed trading around a catalyst.

### Query 3 — Vol Surface (~4 min)
> **Prompt:** "Show me the volatility surface for SPY. I want a table of implied volatility by strike and expiry for the next 3 monthly expirations."

**What Claude does:**
1. Calls `get_options_chain` for SPY with expiry filter
2. Pivots the data: strikes as rows, expirations as columns, IV as values
3. Formats as a clean matrix

**Walk through the output:** point out the vol skew (puts have higher IV than calls at the same distance from ATM — the "smirk"). Explain why: put buyers are paying a premium for downside protection, bid up put IV.

### Query 4 — IV Rank (~3 min)
> **Prompt:** "What's the IV rank for SPY, AAPL, and NVDA? I want to know if options are cheap or expensive relative to the last year."

**Explain IV Rank first:** IV rank (IVR) = (current IV - 52-week IV low) / (52-week IV high - 52-week IV low). A rank of 80 means current IV is near its annual high — options are expensive, good time to sell. A rank of 10 means options are cheap — good time to buy.

**What Claude does:**
1. Queries OHLCV for ATR (as vol proxy) or options data for historical IV
2. Computes the rank inline
3. Returns a simple table: ticker, current IV, 52-week range, IV rank, interpretation

### Query 5 — Best Covered Call Setup (~4 min)
> **Prompt:** "What's the best covered call setup on AAPL right now? I want to sell a call, collect premium, and have a good chance of expiring worthless. Suggest a strike and expiry."

This is the most complex query — Claude has to reason, not just query.

**What Claude does:**
1. Gets current AAPL price from `get_ohlcv`
2. Gets AAPL options chain from `get_options_chain`
3. Filters for calls with 30–45 DTE and 0.25–0.35 delta (standard covered call parameters)
4. Ranks by theta (highest time decay)
5. Returns a recommendation with the premium, breakeven, probability of expiring worthless

**Walk through the recommendation:** this is the moment the whole series has been building toward. A plain English question about a real options trade, answered with real live data from your own lakehouse.

## Key Concepts

**Natural language → SQL → results: the full chain**
The chain is: your English question → Claude parses intent → Claude writes SQL → `query_sql` MCP tool sends it to R2 SQL → Cloudflare scans your Iceberg tables → results return as JSON → Claude formats and explains them. Every link in that chain is something you built and own.

**Where Claude adds value beyond SQL**
Raw SQL can filter and aggregate data. Claude can also: interpret what the numbers mean for a trade, suggest follow-up questions, explain why a metric matters, and combine multiple queries into a coherent recommendation. The RSI screener is SQL. "Is this a good entry point?" is reasoning. Claude does both in the same response.

**The limits of this stack**
Be clear-eyed about what this stack doesn't do:
- No real-time tick data (latency is daily, not sub-second)
- No backtesting engine (you have the data, but need a separate framework like bt or zipline)
- No execution (this is research and screening, not a trading bot)
- No live P&L or position tracking

These are all buildable on top of this foundation — and EP 13 points toward some of those upgrades.

**Own your data, own your edge**
The meta-lesson: every tool in this stack — yfinance, DuckDB, R2, Iceberg, MCP — is open-source or has a free tier. Nothing here locks you into a vendor. Your data is in open Parquet files using an open table format. You can export it to any other tool at any time. In a world where data infrastructure is sold as SaaS, owning the stack is itself a competitive advantage.

## Common Gotchas

- **"Claude gives me a generic answer instead of querying my data"** — Make sure the MCP server is connected. Run `/mcp` to verify. If it's not connected, Claude will answer from its training data, not your lakehouse.
- **"Claude's SQL is wrong and the query fails"** — Show the error to Claude — it almost always self-corrects in one follow-up. Or switch to the raw SQL approach: ask Claude to show you the SQL it's about to run before executing.
- **"The vol surface is formatted badly"** — Ask Claude to "show the vol surface as a markdown table with strikes as rows and expirations as columns." Explicit formatting instructions in the prompt override the skill defaults when needed.
- **"Claude refuses to give trade recommendations"** — Claude will give you data analysis and trade setups but will remind you it's not a licensed financial advisor. Frame questions as analysis ("what does the data suggest") not advice ("what should I buy").
