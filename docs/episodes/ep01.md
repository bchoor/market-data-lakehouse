### Cloudflare R2, Data Catalog, and R2 SQL Explained (~4 min)
Plain-English explanations, no marketing:

**R2** is an S3-compatible object store. Think of it as a folder in the cloud where you put Parquet files. It's cheap and has no egress fees.

**R2 Data Catalog** is a metadata registry. It knows that `r2://your-bucket/ohlcv/` is an Iceberg table called `ohlcv` with these columns and these partitions. Without the catalog, R2 is just files. With the catalog, it's a queryable database.

**R2 SQL** is a serverless SQL engine that reads from R2 via the catalog. You send it a SQL string over HTTP and get back rows. It's like Athena on AWS but built into Cloudflare — no clusters to spin up.

### Apache Iceberg — Why It Matters for Market Data (~3 min)
Iceberg is an open table format for large analytic datasets. Instead of one giant CSV, you have:
- Parquet data files (columnar, fast to scan)
- Manifest files listing which data files exist
- A metadata JSON file with the current snapshot

For market data specifically, Iceberg gives you:
- **Partitioning by date + ticker** — queries for "AAPL in Jan 2024" touch only those files
- **Time travel** — every write creates a new snapshot, old snapshots are preserved
- **Append-only writes** — safe for concurrent or incremental runs; no full rewrites

## Key Concepts

**Apache Iceberg**
An open table format that adds database-like features (snapshots, partitioning, schema evolution) on top of plain Parquet files stored in object storage. The files are still just files — any engine that understands Iceberg can read them. This is why Iceberg data in R2 can be queried by R2 SQL, DuckDB, Spark, or anything else.

**Object Storage vs Block Storage**
Object stores (R2, S3) store files by key. They're cheap, durable, and append-friendly. Block storage (EBS, local disk) works like a hard drive. Lakehouses run on object storage because the data is too large for a database but too structured for raw files.

**Serverless SQL**
R2 SQL has no server to manage. You send a query, Cloudflare runs it against your Iceberg metadata and Parquet files, and returns results. You pay per query (or nothing on the free tier). No cluster, no always-on compute cost.

**The MCP Protocol**
Model Context Protocol (MCP) is the standard that lets AI models call external tools and data sources. In this series, the MCP server exposes your lakehouse to Claude — so "show me RSI < 30 names" becomes a real SQL query against real data.

## Common Gotchas

- **"I don't have a Cloudflare account"** — Sign up for free at cloudflare.com. You don't need to add a credit card for the R2 free tier.
- **"Do I need to follow every episode?"** — No. If you just want the data layer, stop at EP 9. EP 10–12 add the AI interface on top.
- **"Is this production-ready?"** — The architecture is. The scripts are deliberately simple so you can read and modify them. A real fund would add error alerting, retries, and auth. We'll call out those gaps as we go.
- **"yfinance terms of service"** — yfinance scrapes Yahoo Finance. It's fine for research and personal use. Don't build a product that resells the data.
