## Episode Outline

### What Is MCP? (~3 min)
MCP (Model Context Protocol) is an open protocol from Anthropic that lets AI models call external tools and data sources in a standardized way. Without MCP, Claude can only work with text you paste into the chat. With MCP, Claude can call a function on your server, get back real data, and use that data in its response.

Think of it like this: MCP is to Claude what browser extensions are to Chrome. It extends what Claude can do without modifying Claude itself. The MCP server is code you write and run — Claude calls it when it needs data.

### The Four Tools This Server Exposes (~3 min)
Walk through `mcp_server/server.py` at a high level:

1. **`list_tables`** — returns the available tables (`ohlcv`, `options_greeks`) with their schemas
2. **`query_sql`** — takes a SQL string, runs it against R2 SQL (or DuckDB in local mode), returns results as a table
3. **`get_options_chain`** — takes a ticker and optional expiry filter, returns the current options chain with Greeks
4. **`get_ohlcv`** — takes ticker(s) and date range, returns price history with indicators

These four tools are all Claude needs to answer most market data questions. Claude figures out which tool to call, what SQL to write, and how to interpret the results — you just ask in English.

### Adding to Claude Desktop (~4 min)
Find your Claude Desktop config file:
- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

Add the server entry:
```json
{
  "mcpServers": {
    "market-data": {
      "command": "python",
      "args": ["/absolute/path/to/market-data-lakehouse/mcp_server/server.py"],
      "env": {
        "CF_ACCOUNT_ID": "your_account_id",
        "CF_API_TOKEN": "your_api_token",
        "R2_BUCKET_NAME": "market-data-lakehouse"
      }
    }
  }
}
```

Restart Claude Desktop. You should see a hammer icon (tools) appear — click it and verify `market-data` server is listed with its four tools.

### Adding to Claude Code via .mcp.json (~2 min)
In the project root:
```json
{
  "mcpServers": {
    "market-data": {
      "command": "python",
      "args": ["mcp_server/server.py"]
    }
  }
}
```
Claude Code picks this up automatically when you open the project. Run `/mcp` in Claude Code to verify the server is connected.

### First Natural Language Query (~5 min)
In Claude Desktop, type:
> "What stocks in my database have RSI below 30 right now?"

Watch Claude:
1. Call `list_tables` to confirm `ohlcv` exists
2. Call `query_sql` with a WHERE clause it constructed
3. Receive the results and format them as a human-readable response

Then try a harder query:
> "Show me the volatility surface for SPY — give me IV by strike and expiry for the next 3 expirations"

Watch Claude call `get_options_chain` for SPY, receive the full chain, and organize it into a volatility surface table.

### Debugging MCP Connections (~3 min)
Common issues:
- Server not appearing → restart Claude Desktop after config change
- Tool calls returning errors → check the `mcp_server/server.log` file
- Python path issues → use absolute paths in `args` and `command`

Show how to test the server directly:
```bash
# Test the server independently (without Claude)
python mcp_server/server.py --test
# Should print: "4 tools registered. R2 SQL connection: OK"
```

## Key Concepts

**MCP — the protocol that lets Claude talk to external data**
MCP defines a standard JSON-RPC protocol over stdio (or HTTP). When Claude wants to call a tool, it sends a JSON message to the MCP server process. The server executes the tool (runs SQL, fetches data, calls an API) and returns results as JSON. Claude receives the results and continues the conversation. From Claude's perspective, tools are just functions it can call. From your perspective, the server is a Python process you wrote and control.

**Tool design philosophy — fewer is better**
The server exposes four tools, not twenty. This is intentional. If you give Claude too many tools with overlapping purposes, it gets confused about which to call. Four focused tools (list, query, options chain, OHLCV history) cover 95% of market data questions. When Claude can't answer something with these four, it tells you — which is the right behavior.

**Local mode vs production mode**
The server has a `--local` flag that routes all queries through DuckDB instead of R2 SQL. This is useful for: development (faster, free, offline), demos (no Cloudflare dependency), and testing new SQL before it hits production. In production mode, all queries go to R2 SQL. The tool interface is identical — you switch modes by changing one env var.

**Security: what Claude can and cannot do**
The MCP server is read-only. Claude can query your data but cannot write, delete, or modify anything. The `query_sql` tool rejects any statement that isn't a `SELECT`. This is intentional — you don't want an AI writing to your data lake without a human reviewing the write.

## Common Gotchas

- **"The hammer icon doesn't appear in Claude Desktop"** — The config file must be valid JSON with no trailing commas. Use a JSON validator before saving.
- **"Tools appear but calls fail with 'server exited'"** — Check that the Python path is correct and all dependencies are installed in that Python environment. Use `which python` to get the absolute path.
- **"Claude doesn't call the tools, just responds from its training"** — Phrase your question as something that requires current data: "What does my database show for RSI right now?" rather than "What is SPY's RSI?" (which Claude might answer from training data).
- **"The server works in --test but fails in Claude Desktop"** — Claude Desktop inherits a limited environment. Make sure all env vars are set in the `env` block of the config, not just in your shell's `.env` file.
