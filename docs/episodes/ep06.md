## What You'll Build

A live Cloudflare R2 bucket configured for Iceberg table storage, with your table schemas registered in the R2 Data Catalog — the foundation everything in EP 7–9 builds on.

- EP 05 complete (local Parquet files in `data/`)

## Episode Outline

### Cloudflare Dashboard Walkthrough (~4 min)
Walk through the dashboard live:
1. Log in → R2 Object Storage → Create bucket
2. Name: `market-data-lakehouse` (or your preferred name)
3. Location: Auto (or choose the region closest to you)
4. Enable "Jurisdiction: Default"
5. Bucket created — note the public URL (we won't use it — we'll use private access)

Then: Workers & Pages → R2 → API Tokens → Create Token:
- Permissions: `Object Storage:Edit` (for writing files) + `Data Catalog:Edit` (for registering tables)
- Copy the token into `.env`

Also find your Account ID:
- Top-right corner → Account Home → copy the Account ID from the URL or sidebar

### Setting Up .env (~1 min)
```bash
# Add to .env
CF_ACCOUNT_ID=your_account_id_here
CF_API_TOKEN=your_api_token_here
R2_BUCKET_NAME=market-data-lakehouse
R2_ENDPOINT=https://your_account_id.r2.cloudflarestorage.com
```

### Running catalog_setup.py --init (~5 min)
```bash
python cloudflare/catalog_setup.py --init
```

Walk through what this does line by line:
1. Creates the Iceberg namespace `market_data` in the catalog
2. Registers the `ohlcv` table schema (columns, partition spec: by ticker + date year)
3. Registers the `options_greeks` table schema
4. Writes the initial metadata JSON to `R2://market-data-lakehouse/.iceberg/`

Show the output — it should print a table of registered tables with their S3 paths.

### Verifying with --status (~3 min)
```bash
python cloudflare/catalog_setup.py --status
```

Show output:
```
Namespace: market_data
  ohlcv           → s3://market-data-lakehouse/ohlcv/        [OK]
  options_greeks  → s3://market-data-lakehouse/options/       [OK]
```

Go back to the Cloudflare dashboard → R2 → your bucket → browse to `.iceberg/` prefix. Show the metadata JSON files sitting there — this is what makes it an Iceberg table, not just a folder of Parquet files.

### What the Data Catalog Actually Stores (~2 min)
Clarify the architecture: the catalog stores metadata pointers, not data. The catalog entry for `ohlcv` says "this table's current snapshot is at `s3://market-data-lakehouse/ohlcv/metadata/v1.metadata.json`." The data files themselves are in R2 under the `ohlcv/data/` prefix. The catalog is the index; R2 is the storage.

## The Code

```bash
# Initialize catalog (run once)
python cloudflare/catalog_setup.py --init

# Check status (run anytime)
python cloudflare/catalog_setup.py --status

# Re-register a specific table if schema changed
python cloudflare/catalog_setup.py --register-table ohlcv

# Drop and re-create everything (use with caution — deletes catalog entries)
python cloudflare/catalog_setup.py --reset
```

## Key Concepts

**R2 vs R2 Data Catalog**
R2 is the object store — it stores bytes. R2 Data Catalog is the metadata layer — it stores schemas, partition specs, and pointers to current snapshot files. Without the catalog, R2 is just a folder. With the catalog, it's a queryable database that R2 SQL and DuckDB can read. Think of R2 as the filing cabinet and the catalog as the index cards.

**Apache Iceberg metadata structure**
An Iceberg table is a set of files with a specific layout:
```
ohlcv/
├── data/
│   ├── ticker=SPY/
│   │   ├── year=2024/
│   │   │   └── 00001.parquet
│   └── ticker=AAPL/
│       └── year=2024/
│           └── 00001.parquet
└── metadata/
    ├── v1.metadata.json    ← current table metadata
    ├── snap-12345.avro     ← snapshot manifest list
    └── manifest-67890.avro ← manifest file listing data files
```
The catalog points to `v1.metadata.json`. Every write creates a new metadata version atomically. Old versions remain for time-travel queries.

**Cloudflare API Token permissions**
Cloudflare's IAM uses scoped API tokens. For this project you need: R2 Object Storage:Edit (to write Parquet files), R2 Data Catalog:Edit (to register tables), and R2 SQL:Read (to run queries in EP 8). Do not use your global API key — use a scoped token with only these permissions.

**Iceberg partition specs**
Partitioning tells Iceberg how to organize data files. We partition `ohlcv` by `ticker` and by `year(date)`. A query for "SPY in 2024" only opens files in `ticker=SPY/year=2024/` — skipping all other files. Good partitioning is the difference between a 10ms query and a 10-second full-table scan.

## Common Gotchas

- **"403 Forbidden on catalog operations"** — Your API token is missing `Data Catalog:Edit`. Create a new token with the correct permissions.
- **"Bucket name must be globally unique"** — R2 bucket names are scoped to your account, not globally. `market-data-lakehouse` should work unless you've already created it.
- **"The .iceberg/ prefix isn't showing up in the dashboard"** — Run `--init` first. The catalog only writes metadata when you register a table.
- **"catalog_setup.py --status shows tables as MISSING"** — This usually means `--init` ran but the metadata write to R2 failed silently. Check your `.env` for `R2_ENDPOINT` — it must include your account ID in the subdomain.
